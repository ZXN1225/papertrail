# PaperTrail 执行计划

原则：每个阶段有验收记录，完成后暂停等待用户检查；不把阶段规划当成实现，不把离线合成测试当成真实数据质量。具体工具和接口在各阶段开始前再核验当前官方文档。

| 阶段 | 内容 | 主要验收 |
|---|---|---|
| P01 章程与迁移评估 | 需求、来源边界、Agent 架构、测试矩阵；审计旧项目可复用模块 | 本阶段文档齐备；旧项目未改写；迁移决策可审查 |
| P02 新项目骨架 | 独立配置、服务端运行入口、健康检查、锁定依赖、CI 与开发说明 | 空环境安装/启动；Key 缺失时元数据模式可用；密钥不进客户端 |
| P03 OpenAlex 元数据客户端 | 固定 API 客户端、字段白名单、超时/退避/配额观测、来源记录 | 使用少量实时查询和 mock 测试；校验 ID、分页、错误及限流 |
| P04 快照导入与论文目录 | 本地冻结 JSONL/数据库、来源 ID、差异预览、幂等导入、列表/详情 | 可重复导入；保留原始 ID 与时间；未知字段为 null |
| P05 BM25 与检索金标 | 论文查询解析、过滤、BM25 基线、人工标注集与离线报告 | Hit@k/MRR/NDCG、分桶、延迟与哈希报告可复现 |
| P06 Agent Harness 与引用契约 | 固定只读工具、轮数预算、结构化观察、引用校验和拒答 | 工具安全、引用 lineage、缺失证据与无结果反例通过 |
| P07 OpenAlex API 与 Harness 完整化 | 研究工作流所需 Works/Authors/引用关系只读 API；工具注册、运行 trace、错误/预算/时延观测 | 固定 host 和实体路径、字段/参数白名单、单测 mock；Agent 每次运行可审查模型轮次/工具状态/耗时/token；不记录提示词、摘要、密钥 |
| P08 arXiv 第二来源 | 官方 API 客户端、跨源 ID 映射、署名与限速 | 去重有匹配依据；尊重 API 间隔；来源可追踪 |
| P09 许可准入的全文 RAG | 仅对明确许可论文导入全文；切块、BM25、证据片段 | 未知许可拒绝；许可/哈希/位置可追踪；删除与重建流程可测 |
| P10 Embedding / Hybrid 实验 | 候选 embedding、pgvector 或可替换后端、RRF/可选 reranker | 同一数据和题集 A/B；记录 Hit/MRR/NDCG、成本、时延与决策 |
| P11 前端研究工作区 | 查询、过滤、结果、论文详情、比较与 Agent 引用展示 | 基础 E2E、空结果、错误状态、来源链接和键盘可用性 |
| P12 端到端评测与作品集交付 | 固定 benchmark、Agent 指标、成本/延迟仪表、README 演示 | 一键复现、报告和演示脚本；无未经验证的性能声明 |

## 迁移策略

- PaperTrail 根目录迁移完成后，旧电脑项目从发布工作树移除；本机归档放入 Git 忽略的 `.local/legacy-computer-project/`。
- 新产品先放在 `` 子目录，作为独立边界开发；阶段验收后再考虑拆成独立 GitHub 仓库。
- 借鉴而不直接耦合：旧项目的工具白名单/Harness、模型 Provider 适配、会话与运行事件、服务端错误边界、BM25 与评测脚本的设计。
- 暂不跨目录导入旧电脑业务模块。若需复用代码，先抽出与领域无关的模块并为新项目建立独立测试；优先复制经审查的小型通用实现，避免运行时依赖旧产品。
- 不复用商品 SKU、价格快照、兼容性规则、商城授权注册表、电脑表单与合成目录。

## P01 验收

- 用户目标、来源策略、全文许可边界、工具白名单、检索策略和评测指标均写入规格。
- 执行顺序、阶段停止点和迁移边界清楚。
- 只创建规划文件和配置示例，没有外网采集、LLM 调用、数据库迁移或真实密钥。
- 根项目旧文件保持不变；新分支只添加论文子项目及根级进度台账记录。

## P02 验收

- 可用 Python 3.12 与锁定依赖从新环境安装，服务通过单一工厂入口启动。
- `GET /api/health/live` 明确进程存活；`GET /api/health/ready` 只报告本阶段实际依赖，不把尚未实现的数据库或外部来源伪报为已连接。
- 无 OpenAlex/LLM/embedding 密钥时应用仍可启动；`.env.example` 不含真实凭据，服务端配置不回传密钥。
- 测试覆盖健康状态、默认配置以及非法 Provider 配置；CI 执行 lint、格式检查和测试。
- 开发文档提供 Windows PowerShell 与通用命令；锁文件与 pyproject 一致，且 `git diff --check` 通过。
- 不发起外部来源或模型请求，不创建数据库，不迁移/删除旧电脑项目代码，不推送 GitHub 或清理分支。

## P03 验收

- OpenAlex 生产客户端仅访问固定 `https://api.openalex.org`，Key 通过 Authorization Bearer 请求头传递，不拼入 URL；允许 keyless 小规模试用。
- 搜索输入、页大小与深度有界；仅请求批准的论文元数据字段，不请求或下载全文。
- 校验分页 envelope 与 work ID，忽略未知上游字段；错误映射区分认证失败、限流、上游错误、超时与响应格式错误，不向客户端透出 Key 或原始异常内容。
- 有限重试仅针对 429/暂时性 5xx，尊重有界 Retry-After；暴露可用于观测的速率额度头，不记录密钥。
- 本地只读搜索 API 能返回来源 ID、标题、作者/年份等字段；未设置 Key 时保持可运行。
- Mock 契约测试覆盖成功、分页、请求域名/认证头、无 Key、429、401、5xx/超时、损坏 JSON 和参数边界；任何测试都不需要外网。
- `.env` 指引清楚说明 OpenAlex 和 OpenAI Key 的独立用途、填写方式、重启后生效、绝不提交；本轮只使用 OpenAlex，不调用 OpenAI。
- 外网真实 Key 烟测仅在用户将 Key 写入本机 `.env` 并主动提供可测试信号后执行；未执行则如实标记待验证。旧代码与 GitHub 分支均不清理。

## P04 验收

- 使用 SQLite 和版本化 SQL 迁移；空库能自动初始化，迁移多次可安全重复，未知/高于当前版本的数据库状态明确报错。
- 每次同步生成不可变导入快照，记录 source、查询参数（不含认证头/Key）、OpenAlex 时间、API 匹配总数、接收行数、数据许可标记、稳定内容哈希。
- Work 使用 OpenAlex 稳定 ID；每个内容版本保留经过字段白名单解析的源记录 JSON、来源 URL、首次出现快照、观察时间、解析器版本和 SHA-256；同一 ID 发生变化时追加版本，不覆盖历史；相同数据重复导入不重复建内容版本。
- 单页导入 CLI 的 page size 最大 100（与 OpenAlex 官方 Works 接口上限一致），不允许无界同步；只请求 Works 元数据，不抓全文/文件，也不将 Key 放进快照或日志。
- 提供本地目录分页、精确详情和快照 lineage 只读 API；空库给出空列表/404，不造演示论文；返回结果带来源 ID、URL、观察时间和当前内容哈希。
- 抽取摘要必须可复现；缺摘要保持 null，摘要倒排索引异常/超界不能崩溃或伪造摘要。
- 测试覆盖迁移、导入/重复导入/数据变更、历史版本、回滚、字段缺失/未知字段、摘要重建与边界、查询分页、详情 404、快照 lineage、Key 不持久化。
- `.env` 与本地数据库保持 Git 忽略；测试数据库使用项目内临时目录并清理。
- 用已配置 OpenAlex Key 只导入一页最多 10 条作为本地真实数据冒烟，输出只报告摘要计数/hash 前缀，不打印用户密钥或论文原始摘要；用户数据仍仅在本机数据库，不提交。
- 不清理旧电脑代码/分支；相关通用代码迁移还未完成，待后续迁移与验证后再审查清理。

## P05 验收

- 使用本地冻结目录快照实现确定性 BM25，不在线调用 OpenAlex、不改变测试/真实命名空间；语料、算法和 tokenizer 版本写入报告。
- 人工标注固定查询与 graded qrels，每条 qrel 指向已有真实 OpenAlex ID；说明标注范围和小数据局限，不把 benchmark 分数包装为泛化结论。
- 计算 Hit@k、MRR@k、NDCG@k、分桶宏均值、延迟和空结果率；定义无 qrel 查询的处理规则、tie-break 与 top-k。
- 离线 CLI 输出可重复 JSON 报告，其中含 dataset/corpus 哈希、快照、配置、查询数、文档数和运行耗时；报告文件默认不提交。
- 单元测试覆盖 CJK/英文分词、BM25 基本排序、指标计算、无相关项、未知 work ID 与确定性重跑；ruff 和全后端测试通过。
- OpenAI 与 embedding provider 维持 disabled；全文不下载。旧电脑目录和分支仅在复用 Agent/Harness 部分完成并验证后再评估清理。

## P06 验收

- 固定只读函数工具由严格 JSON Schema 与 Pydantic 双重校验；白名单仅覆盖本地论文搜索、详情、相关文献/比较和明确不可用的全文证据入口。
- Harness 强制最多 4 轮、8 次工具调用、45 秒总耗时与有界 observation；异常参数、未知工具、重复 call id、模型拒答和上游失败都有确定状态。
- OpenAI Responses API 使用严格工具 schema 和结构化最终回答；模型只决定何时/如何调用允许工具，论文搜索、ID、摘要字段和引用 URL 都由服务端提供。
- 引用输出由服务端针对本轮工具观察做 allow-list 验证；未观测引用会被拒绝，不会映射到未执行的论文。
- 论文来源元数据是 untrusted data；模型不拥有 arbitrary URL、shell、filesystem、SQL、HTTP client、数据库写入权限。
- Mock 测试覆盖工具选择/参数边界、轮次与总调用上限、prompt injection、引用验证、无数据/无全文证据、LLM disabled 和 Responses API JSON/错误；测试不得真实调用 OpenAI。
- 真实 LLM、检索质量、RAG 答案证据与成本评估在完整运行阶段执行；P05 候选 qrels 未复核前继续标注为 provisional。

## P12 完整运行测试矩阵

- **数据/检索**：固定 OpenAlex snapshot、人工审核 qrels、BM25 与后续 dense/hybrid 用完全相同的 query/corpus；报告 Hit@1/3/5/10、MRR、NDCG、分桶、空结果率、索引/数据哈希与检索延迟。
- **RAG 答案**（P08 后）：针对有许可全文的 QA 集测引用 ID/段落定位正确率、引用 precision/recall、答案 claim 的证据支持率、证据不足拒答正确率；prompt injection、无全文权限、缺片段、跨论文冲突均纳入负例。
- **Agent**：固定多轮任务与预期工具序列/参数，测工具选择准确率、参数合法率、工具成功率、最多轮数/调用数、无结果/模型错误恢复；Citation contract 检查只接受实际工具 observation 中的 OpenAlex ID/URL，伪造引用须被拒绝。
- **工程**：测端到端 p50/p95 latency、每次运行输入/输出 token、可观测费用估计、异常/超时/限流率与取消情况。先用 mock 做确定性 CI；用户确认后再用少量 live OpenAI queries 做受限烟测，报告模型、提示词/工具版本、数据快照、token 与实际观测费用。
- **发布报告**：固定查询与 gold qrels 由人工复核并锁定哈希；公开说明题数、文献数、许可、运行日期、硬件/软件、失败案例和未覆盖内容。小型项目演示可以报告结果，但样本不足时必须标记 exploratory，不能声称通用质量提升。

真实 OpenAI 调用不会由 CI 或 mock 测试隐式触发。P12 会按“离线可重复 benchmark → Agent/RAG mock 与红队反例 → 经用户确认的小批量 live 运行”分开记录，避免混淆工程正确性与线上模型质量。
