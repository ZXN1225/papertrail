# PaperTrail 项目规格

更新日期：2026-09-25。状态：P01—P37 已完成；P36 人工盲审池内排序和 P37 助手/人工评分一致性均仅属探索诊断，不支持总体质量声明或 LLM-as-judge 校准声明；仓库已更名为 `papertrail` 并发布到唯一远程分支 `main`。OpenAlex/arXiv 元数据、受限 Agent、跨来源发现与 DOI 归并、引用网络扩展、许可准入全文 BM25 RAG、可选 Dense/Hybrid 检索及 Web 工作区均已接入。文献检索支持按 10 条一批加载后续结果；远程来源在检索时应用年份过滤；Agent 可使用左侧当前搜索上下文和有限近期对话历史。首页主标题为“Agent 文献检索分析系统”。README 已按研究需求整理策略选择理由，并列出 P05/P14/P17/P36/P37 评测迭代与质量声明边界。P36 完成 101 个候选的盲审及受限池内排序对照；P37 完成 101 对助手建议和人审等级的离线一致性诊断。

## 1. 产品目标

构建一个可演示、可评测的论文检索与研究助理 Agent。用户以自然语言描述研究问题或兴趣，系统检索真实论文、排序并解释匹配理由；用户可以查看论文元数据、摘要、公开来源、作者、年份、主题与引用关系。后续研究总结必须将事实主张链接到具体论文证据，并对证据不足的内容明确标记。

本项目是学习与简历项目，不宣称替代系统综述、专业同行评审或研究者判断，不自动判断论文结论为真。

## 2. 来源与许可

### 首发来源：OpenAlex

- 首期只接收 API 返回的学术元数据字段；保留 OpenAlex ID、原始记录 URL、查询时间、数据版本/快照时间和映射版本。
- OpenAlex 数据当前以 CC0 发布；每次上线前仍需复核现行 API 条款、字段语义和服务额度。
- API Key 是可选的服务访问凭据，不是论文全文许可，也不进入浏览器、日志或 Git。

### 后续来源：arXiv

- 使用官方 API 查询论文元数据；遵守 API 使用条款、请求节流和指定署名要求。
- arXiv API 元数据、论文文件和论文内图表的许可不是同一概念。未经记录并核对具体许可，不下载、保存、切分或展示全文。
- P08 已接入官方 arXiv Atom API，支持有界搜索、精确 ID 查询、SQLite 快照和不可变版本；单进程请求间隔至少 3 秒，默认每页不超过 25 条。元数据自动跨源关联只采用唯一精确 DOI，歧义或冲突不自动合并。

### 全文边界

- 只有能解析到明确许可且许可允许本项目拟定处理方式的全文，才可进入全文索引。
- 许可未知、仅有开放访问标识、或只有可读网页，不自动视为允许保存和重展示。
- 保留原始来源 URL、许可名称/URL、许可检查时间、内容哈希、抓取时间和处理版本；权限不明确时仅保留元数据与外链。
- P09 本地全文导入采用人工核对确认，仅白名单 `CC0-1.0` 与 `CC-BY-4.0`；只读 UTF-8 `.txt`，不自动下载或抓取。每个结果携带原论文链接、许可/证据页面、署名、chunk ID 与字符位置。具体文件版权仍由导入者逐篇确认；系统白名单不是法律意见。

## 3. 用户流程

1. 输入研究问题，可补充年份、学科、作者、开放许可等过滤条件。
2. 系统将明确提出的年份范围和开放获取条件交给结构化白名单筛选，检索论文并返回排序结果和可解释字段。OpenAlex 按出版日期过滤；arXiv 按提交日期过滤；本地目录年份筛选作用于已载入记录。
3. 需要更广发现时，Agent 可将 OpenAlex 与 arXiv 作为互补元数据源并行用于查询规划（由模型依次调用工具）；年份筛选按来源支持的字段分别执行，OpenAlex 的 OA 过滤不套用于 arXiv。需要拓展时，再沿 OpenAlex Works 的参考文献/被引元数据执行有限一跳发现。
4. 仅当 OpenAlex 与 arXiv 返回完全相同的 DOI 时才跨源合并；以 OpenAlex 作为主记录并保留 arXiv 备用链接。缺 DOI 或 DOI 不同的记录独立展示。
5. 用户选择论文进行摘要、主题比较或延伸阅读。
6. Agent 在只读工具白名单内查询论文、引用关系和许可允许的证据片段；左侧搜索条件由后端重新读取为可信元数据，近期对话历史只用于解析指代，不作为事实证据。
7. 输出逐条引用来源、发布日期、证据片段定位、缺失信息和不确定性；无支持证据时拒答或说明缺口。

## 4. Agent 与工具边界

计划工具：

- `search_papers`：搜索与过滤作品元数据。
- `get_paper_details`：读取单篇作品的规范化详情。
- `find_related_papers`：在本地目录中按标题/摘要词法相似度发现候选（不是引用网络）。
- `expand_openalex_citations`：沿一个 OpenAlex Works ID 读取一跳参考文献/被引 Works；每方向最多 10 条，仅作为发现线索。
- `retrieve_paper_evidence`：只检索许可准入的全文片段；全文功能未实现时明确返回不可用。
- `compare_papers`：由后端确定性汇总选定作品的结构化字段，再由模型组织文字。

模型不得自由访问任意 URL、任意文件、SQL 或 shell，不得直接写数据库、发起下载、改变许可状态或生成虚构论文/引用。所有工具使用 Pydantic 契约、次数与时间上限；最终论文列表和引用必须来自已执行工具的结构化结果。

### 4.1 Harness 组件与当前工具面

Harness 按职责拆分为：模型适配器（Responses API 与可替换 mock）、决策循环/步数预算、严格工具注册表、Pydantic 参数与返回契约、只读执行层、有界 observation、引用证据账本与终答验证、deadline/token 统计、脱敏 run trace、离线 eval 接口。当前不使用多 Agent 或自由规划器：单 Agent + 明确工具契约更易审计；只有后续评测证明有必要才引入专业子 Agent。

当前生产模型运行实际注册最多 13 项受限只读工具：本地 BM25 搜索、精确作品详情、词法相似作品、2—5 篇元数据对比、全文证据检索；OpenAlex Works 搜索/详情、受限年份/OA 筛选、单种子一跳引用拓展、Authors 搜索/详情、作者作品列表；arXiv 元数据搜索/精确读取。来源工具仅在对应客户端启用时展示；固定官方 host，ID/查询/页大小有界。Agent 指引在需要广覆盖时结合 OpenAlex 和 arXiv；OpenAlex 年份是出版年过滤，arXiv 年份范围按官方 API `submittedDate` 过滤。两者年份语义不同，arXiv 不承诺 OpenAlex OA 条件。跨源只以完全匹配 DOI 去重，保留备用来源链接；没有 DOI 时不按标题猜测合并。OA 元数据筛选不代表全文许可。arXiv 工具只读元数据，不开放论文文件请求、任意网页抓取或数据库写入。

Harness 强制结构化终答；候选论文、摘要与引用只能来自本轮已执行工具观察，引用由 allow-list 校验。若终答格式无效且剩余模型步数允许，Harness 仅尝试一次无工具格式修复；修复结果仍须通过相同 JSON 契约与引用 allow-list 校验。P30 额外给出不含回答正文的结构化输出错误类别，便于区分 JSON 解析、schema 与引用校验失败。OpenAlex 引用对象保留工具实际返回的出版年份与引用方向/种子 ID；前端来源卡片可据此显示年份、“种子论文的参考文献”或“引用种子论文”，普通元数据引用没有方向时不补造关系。运行记录仅保存事件类型、工具名称、状态、白名单内的安全错误码、耗时和 token 数；不保存用户问题、工具参数、论文正文、凭据或原始异常内容。同一 Agent 运行中某来源失败后不会再次调用该来源。运行记录随响应返回；持久化、导出和仪表盘仍属后续工作。

`retrieve_paper_evidence` 仅查询当前人工批准的本地全文版本，最多返回 8 个片段；citation 包含许可署名与命中证据定位。未获准文本不进入索引；撤销命令清除文档全部全文版本/切片，并留存不含正文的哈希删除审计。

## 5. 检索与评测

先用可冻结的 OpenAlex 元数据/摘要快照建立 overlap 与 BM25 基线。每条评测查询具有稳定 ID、意图桶、相关论文 ID 与 graded relevance；评测数据不能因在线查询结果变化而静默改变。

检索指标至少包括 Hit@k、MRR@k、NDCG@k、分桶指标、查询均值/P95 延迟、空结果率与数据集哈希。后续答案评测单独量化引用精确率/召回率、可验证主张比例、不可回答问题拒答正确率、工具选择/参数合规率、端到端延迟和模型/API 成本。LLM-as-judge 只能作为补充，需与人工样本校准，不取代确定性指标。

Synthetic 查询和文献只用于代码单元测试及离线评测管线验证，统一 `synthetic=true`、`TEST-*` 标识并与真实来源快照隔离；不能用于报告真实数据质量。P05 qrels 在人工逐项复核完成前不能称为 gold。

Embedding/Hybrid 已完成初版；固定 TEST 向量报告只验证 BM25、Dense、RRF 管线，不代表真实语料/模型质量。当前可选 Dense/Hybrid 模型为 `text-embedding-3-large`（3072 维）；历史 P14 小规模对照运行使用 `text-embedding-3-small`，不能与 Large 新运行混为一谈。P13 qrels 未经人工核验，因此 Large 同题复评仍只作探索诊断；固定 TEST 向量报告不代表真实语料/模型质量。BM25 继续作为默认检索方式。

## 6. 数据模型原则

- 作品使用来源稳定 ID；跨来源匹配 DOI、arXiv ID 等只保存可验证的匹配依据，不靠标题相似度静默合并。
- 展示层的跨源 DOI 去重只合并规范化后完全相等的 DOI，并保留次来源标识/URL；缺少 DOI 或 DOI 冲突时保留独立作品。
- 日期、作者、venue、主题、引用、摘要保留原始来源字段与规范化字段。
- 缺失字段保持 null；不从模型记忆补足出版事实、实验结果或引用。
- 每次导入保留来源快照、采集时间、解析器版本与内容哈希，支持增量重跑和差异审查。
- 全文与元数据许可分开建模；索引记录能追溯到作品、来源位置和许可检查。

## 7. 非功能与安全要求

- OpenAlex/arXiv Key、LLM Key 和数据库凭据仅由服务端读取，示例文件不含真实密钥。
- 固定官方 API 基址、超时、并发和退避；不实现通用网页抓取工具。
- 对提示注入与外部文档指令采用不可信数据处理；论文正文不得提升工具权限。
- API 错误、来源限流或 LLM 不可用时降级到可用的确定性搜索，不伪造成功。
- 记录每次检索和 Agent 运行使用的数据快照与配置版本，便于复现。

## 8. 项目验收愿景

- 能从批准来源检索可核验的真实论文记录，并逐条显示来源链接。
- 元数据搜索、过滤、相关论文与 citation 输出均有稳定测试。
- Agent 不能调用未登记工具，不能编造检索结果，工具失败与无结果状态可见。
- BM25 结果可复现；后续检索增强须用同一冻结题集展示量化差异。
- 全文流程在无许可/未知许可时明确拒绝入库；明确许可内容能够保留许可和证据 lineage。
- 清楚报告测试环境、数据快照、API/模型成本、未覆盖场景和失败项。
