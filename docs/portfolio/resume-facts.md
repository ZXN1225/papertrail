# PaperTrail 简历事实表

更新时间：2026-10-15（v27 上线活动索引 + AI 标注评测完成）。只使用有当前代码或验收记录支持的事实；不要把探索性结果改写成产品质量承诺，也不要把 **AI 标注/AI 复核**写成人工验收。

## 本轮新增、可直接写进简历的事实

- **许可全文解析与索引升级**：把 9 篇 CC BY 4.0 论文（217 页）的全文索引从 `pdfplumber-layout-v21` 升到 **v27**，活动库共 **3,294 个 chunks**；升级前后逐篇 lineage 审计 **9/9 verified**（来源、许可、PDF SHA、parser 版本、chunk 数与逐 chunk 哈希一致）。证据：[升级记录](../research/R02-v27-parse-upgrade.md)。
- **修掉表格解析的两个静默缺陷**（最典型的"结果看起来对、实际错"）：
  1. `Table.extract()` 的推断列边界落在表头字形之外时**静默丢词**（实测丢了 `UMA`、`max_k p_k`）——改为按整表/单元格字符预算回挂缺失词，且**拒绝重复**；
  2. pdfplumber 行边界切在单元格两行之间时，续行被当成独立行、原行该列为空——改为受列宽与行距约束的续行合并。
  新增 **6 个合成回归用例**（含"已在他行出现的词不得重复""单字符在他处出现也不得漏判"两条防回归守卫）。
- **建立了可复现的解析复核链路**：此前复核包是一次性脚本产物、换 parser 版本无法复现；现由 `tools/generate_parse_review.py` 一条命令重建草稿/复核包/manifest，并交给**独立 AI Agent 复核**（两轮，复核者不知晓我的结论）。
  复核确认上述修复有效，并**找出我没发现的缺陷**——其中一个是由图形文字层冒充的 `table` 元素（带伪造的 `Table 1` 标题、把坐标轴数字当表格）。据此新增"表格候选完全落在图形区域内即拒绝"的规则并补测试。
- **在真实语料上建成 53 题 AI 标注评测集并跑出指标**：44 道可答题（每题绑定真实 `chunk_id` + 逐字原文片段）+ 9 道不可答题；标签的逐字引用、来源/页码/元素类型、负例事实的全语料缺失都由构建器**机械复核**（本次丢弃 1 条不合格标签）。结果（全库 3,294 chunks/查询，0 次 provider 调用）：**证据命中 @1 = 59.1%、@8 = 88.6%**；按题型 `figure_caption` 5/5、`single_fact` 22/24、`multi_hop` 11/12、`table_lookup` **1/3（明确短板，与表格解析缺陷方向一致）**；BM25 top-1 分数上可答题均值 **32.5**、不可答题均值 **18.3**，本样本中不可答题最高分低于可答题均值。证据：[AI 标注评测记录](../research/R01-R03-ai-labeled-evaluation.md)、[升级记录](../research/R02-v27-parse-upgrade.md)。
- **修复了仓库自身的可复现性**：历史遗留的受限临时目录会让规范命令直接失败（pytest 收集阶段 57 个 `PermissionError`、`ruff format` panic）；通过 pytest/ruff 配置修复后，**336 项测试可正常收集、291 passed / 0 failed**，OpenAPI 契约未变。

## 可写入项目经历的事实（沿用早期已验证部分）

- 构建 FastAPI + Next.js 论文研究助理，集成 OpenAlex/arXiv 元数据、本地 SQLite 版本快照、许可全文 RAG 与 Web 工作区。证据：[项目说明](../../README.md)、[项目规格](../PROJECT_SPEC.md)。
- 实现固定只读工具注册表和 function-calling Harness，具有步数、工具次数、deadline、token 预算、取消状态、引用 lineage 检查和拒答状态；每次模型请求前按输入上界预留额度并据此收紧输出上限。证据：[README Harness 设计](../../README.md#agent-与-rag-设计)、[R04 验收](../research/R04-agent-runs-acceptance.md)。
- 为运行记录保存问题哈希、状态、用量计数和脱敏 trace，不保存问题正文、答案或论文摘录（**因此重启后无法自动重放**：账本按设计不含正文）；实现重复 run ID 拒绝、状态查询、协作取消和孤立任务中断识别。
- 集成三个带 registry/hash 校验的产品 Skills 与只读 MCP stdio Server；用户在桌面 Host 中确认 5 个工具可用并实际检索一篇许可论文（仅覆盖一个 Host、一篇论文）。
- 实现默认关闭的 Multi-agent 实验协调器：最多 3 个顺序 worker、共享观测预算、隔离单 worker 失败；真实六题对照中仅 1/6 达成并获支持的 consensus，成本比约 **2.20**（高于路线图 1.5 倍门槛），故**不接入生产默认路径**。
- 检索方法对照：Hybrid 的 Hit@1 / MRR@10 = 0.833 / 0.917、Dense 的 NDCG@10 = 0.843（P10，8 查询 × 10 篇人工复核 qrels）。

## 不应写成的结论

- "RAG 准确率提升 X%"：没有本轮许可语料上的人工 evidence-level 对照；AI 标注不能当人工金标。
- "解析准确率 88.6%"：88.6% 是**检索命中率**，且题目写自被评测索引本身，不能当解析或检索的通用质量。
- "多 Agent 优于单 Agent"：真实对照成本比 2.20 且仅 1/6 consensus，默认不接入生产。
- "支持所有 PDF/表格/图表"：表头切词/错列、OCR、图像像素语义均未解决。
- "可恢复任意中断会话"：账本按设计不保存问题正文，重启后只能由调用方重新提交问题。
