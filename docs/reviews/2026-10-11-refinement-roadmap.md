## 1. 工作方式

每阶段按以下流程完成：

1. 用户确定当前目标与预算；写明用户故事、输入/输出、验收条件和非目标。
2. 检查已有状态，建立可比较 baseline；数据许可/人审/真实模型开销明确登记。
3. 记录 ADR，实施小范围改动；接口同步 OpenAPI，数据变化通过迁移，保持旧输入兼容与回滚路径。
4. 运行相关工程回归，再运行该阶段质量评测；记录命令、环境、退出码、失败和未执行项。
5. 交付本机可运行演示、结果摘要与失败例；用户检查后记录 accepted 或 rework。
6. 同步 TASKS/PROGRESS；发布需用户另行授权。用户验收未完成时不推送，不把阶段实现等同于验收。

建议将台账状态拆成 proposed / implementing / automated_checks_passed / quality_evaluated / user_accepted / paused，并将 evidence_status 单独记录。后续更新现有流程时通过文档 ADR 统一，不在本轮批量重写历史 P 阶段。

## 4. 建议验收门槛

以下数字是首轮可讨论的项目目标，**不是行业标准、不是当前成绩**。在开发集评估可行性后冻结；保留测试集只用于最后评价。未达标记录 rework，不缩小分母或把未知题计成功。

| 验收项 | 建议首轮门槛 | 说明 |
|---|---|---|
| 关键不变量 | 全部指定用例通过 | 禁止越权、伪造 ID、撤回/旧版正文泄漏、secret 泄漏、预算继续执行 |
| PDF 支持范围 | 每个支持桶至少 2 个文档样本；人审证据定位正确率目标 ≥95% | 不支持 OCR/复杂结构须明确标注；图注和表格另报指标，不混成一个“解析率” |
| 检索 | gold evidence recall@10 目标 ≥85% | 按表格/正文/跨论文分桶；标签映射正确才计算 |
| 回答 | 人审逐主张支持率目标 ≥95%；完整任务成功率 ≥80% | 两项必须同时满足；事实不全、数值/设置错判任务失败 |
| 不可答与可答 | 不可答正确拒答率 ≥90%；可答误拒率 ≤10% | 拒答与部分成功单列；不能通过全拒答过关 |
| 原文追溯 | 每个输出的事实主张都具有合法本轮证据绑定，缺证据项被删去或明确标未知 | 合法绑定是代码 gate；语义支持仍用人审评估 |
| MCP | 指定的真实协议与直接调用契约用例全部通过 | 含超时/坏参数/资料撤回/未知工具；记录版本与客户端 |
| Skills | 选择与权限用例通过，同题报告完整 | 不预设必然提升；无收益可收缩范围 |
| 多 Agent | 建议 task success 绝对提升 ≥5 个百分点，费用不超过 baseline 的 1.5 倍，且无证据/安全退化 | 仅是启用目标；40 题下 5pt 只有约2题，必须扩样或复核不确定性，不能宣称显著 |
| 时间/费用 | R01 根据用户环境冻结目标、超限率和费用上限 | 先量 baseline；不凭空承诺云 API p95 或本机并发 |
| 工程命令 | 应执行命令退出码 0，未执行有原因 | 浏览器用例打印通过但进程挂起不算整套命令成功 |

所有比例报告 numerator/denominator、题型、模型与次数；3 次 trial 按同一道题聚合稳定性，不写成三倍独立样本。多 Agent 最佳一次与单 Agent 平均值不能相比较。

## 5. 测试执行层次

- **每次代码变更**：相关单元/契约测试；schema、引用位置、版本过滤、错误分支与预算。不访问真实库，不默认消耗付费 API。
- **阶段交付**：根目录 `git diff --check`；backend 的 locked Ruff check/format、pytest、OpenAPI 导出与差异检查；web 的 format/typecheck/build/E2E；两端依赖审计。按 AGENTS.md 使用锁定环境，不以“修复测试”为由覆盖用户数据。
- **质量实验**：独立 TEST 合成回归 + 本机许可真实语料评测；真实资料使用独立评测 namespace/数据库，与个人研究库隔离。只有合成数据标 synthetic=true，真实许可资料不得伪标合成。
- **付费运行**：先给出模型、题数、trial 数、费用上限与停止条件，按用户已授权范围执行。记录失败/重试费用，禁止失控批跑。
- **用户验收**：用户选择论文并确认许可后，核验成功、缺证据、跨论文不可比、表格数值、恶意文档、撤回、超时/取消和恢复；结果绑定运行与数据版本。

以上数字是提案阶段的建议门槛；实际实现与测试状态以路线图 JSON、`docs/PROGRESS.md` 和根目录 `current_contexts.md` 为准。四篇许可 PDF 已完成本机导入，其中新三篇的主要片段已获用户抽样核验；真实模型回答质量和 R07 收益对照仍未验收。

## 6. 后续改进重点

建议首先完成 R00 + R01，并在 R02 前向用户展示：当前 baseline、10—12 篇候选文档的许可核验表、40 题定义、失败分类、解析器比较成本与首版数据契约。用户确认后，再实施结构解析与逐主张引用。
