# 数据来源登记与验证计划

本轮只建立登记表，没有访问或采集以下来源，没有验证许可、API 权限或商品字段。用户附件中的研究记录属于原文历史信息，不作为本轮验证成果。当前审核通过 SKU=0，报价=0，已发布数据版本=无。

| 来源类别 | 候选入口 | 当前状态 | 下一轮样本与验收 |
|---|---|---|---|
| CPU | https://www.intel.com/content/www/us/en/ark.html 或 https://www.amd.com/en/products/specifications.html | not_verified | 选定一源至少 5 个精确型号；socket、内存支持、功率口径、证据定位与时间 |
| 主板 | 品牌精确产品页、CPU 支持表、BIOS 和手册；品牌待样本核验后确定 | not_verified | 至少 5 型号；board revision、CPU/最低 BIOS、尺寸、接口共享；实际出厂 BIOS 不可猜测 |
| 笔记本 | https://psref.lenovo.com/ | not_verified | 至少 5 个精确 MTM/PN；CN SKU 覆盖、屏幕/内存配置、地区与来源；平台可选配置不当 SKU |
| 报价 | https://open.jd.com/ 或供应商文件/人工报价 | not_configured | 未提供接口权限；至少 5 条真实报价或明确失败证据；商家、SKU 匹配、税运费、资格、时效 |

下一轮先核验访问和条款，记录每源的允许用途、再分发范围、缓存期限、频率与检查时间。公开可读不等于批量抓取或再发布许可。遇到登录、验证码或限制时记录失败，不绕过。

## 验证报告格式

每个来源分别记录：入口、实际访问时间、访问方法、条款与权限证据、样本 ID、精确 SKU、字段覆盖、字段定位、缺失/冲突、是否允许发布、失败原因及替代路径。失败记录保留可定位 URL、错误状态和尝试时间；不能用“可能受限”替代实际证据。

验收结论分为：可读取 / 精确身份可确认 / 关键字段完整 / 权限可用 / 可发布，不能只给一个“成功”。至少一组真实数据在 P2 完成导入、审核和查询闭环。需要许可而未确认时保持待审。

## 人工报价路径

设计采用 `ManualOfferProvider`（尚未实现）。录入方提供真实商家/来源、地区、货币、分单位价格、运费与税费口径、资格、库存、观察时间和到期时间，并经审核发布。未知费用不填 0，缺总价时不得声称预算内。API Provider 未获权限时保持未配置。

模板：[来源](../data/manifests/source.template.json)、[人工采集单](../data/samples/collection.template.json)。两者均为不能直接发布的空模板，不是已取得的数据或正式导入 Schema。
