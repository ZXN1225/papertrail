# T10 验收（实施前固定）

步骤 12 保存确定性推荐结果的不可变快照，并提供修订、比较和 Markdown/JSON 导出。

- 创建快照时校验当前会话对画像和指定画像修订的所有权；服务端重新执行对应的 PC 或笔记本确定性求解器，不接受客户端写入结果、价格或兼容性结论。
- 每次修订都创建同一 lineage 的新快照；旧快照及其输入、结果、数据版本和报价到期时间永不更新。
- 仅保存当前求解器给出的数据版本与候选；读取时根据保存的报价到期时间标识 `current`、`historical` 或 `unknown`。历史快照不是“当前预算内”的新声明。
- 所有读取、修订、比较和导出从会话所有权推导；跨会话统一不可见。创建与修订必须有 Idempotency-Key；同路径、同会话、同键而请求不同返回 409。
- 比较限定 2—3 个已拥有快照，价格差基于各快照保存的首选方案总价；没有总价则差值为 null。Markdown 不输出原始不可信 HTML。
- 数据库变更使用 0005 迁移；测试覆盖幂等重放/冲突、历史不改写、所有者隔离和导出，真实 PG 环境下执行迁移与 API 集成测试。
