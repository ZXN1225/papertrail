# P31 检索结果逐批加载

日期：2026-09-25。状态：实现与自动验收完成；年份检索缺陷由 P32 追加修复。

## 问题与选择

OpenAlex、arXiv 的检索 API 和本地目录本身都支持分页，但 Web `/api/search` 固定只请求第一页 10 条，页面也没有后续页控件。匹配总数很大时，用户无法浏览更多候选。

使用“加载更多”追加式交互：保持初始结果紧凑，用户需要时再请求下一页并保留当前结果。这样比一次取回大量数据更节制，也适合结果数量未知的检索。OpenAlex 与 arXiv 每次加载 10 条；本地库分别按两个来源 offset 加载，每个来源每批最多 10 条。不同来源的记录按现有本地展示规则排序。

## 实施

- Web 搜索代理接受 1–1000 页码，并将其映射为 OpenAlex `page/per_page`、arXiv `start/max_results`、本地目录 `offset/limit`。
- 响应提供 `page`、`hasMore` 和上游 10,000 条安全边界提示；前端追加新页并按来源 ID 去重。
- 首版年份筛选只覆盖已载入结果，用户验收时发现其可能导致“有大量匹配但当前 0 条”；此问题已在 P32 修复：远程来源请求和每个翻页请求都带年份条件，本地库仍筛选已载入记录。
- 未改变固定来源 host、后端 API 契约或全文获取行为。

## 验收

- Playwright E2E 验证第二页请求使用 `page=2`、追加结果保留第一页、最后一页隐藏按钮：18/18 三个视口用例通过。
- Web Prettier、TypeScript、隔离 Webpack production build 通过；后端 116 项 pytest、Ruff 和 OpenAPI 导出通过。根 `git diff --check` 通过。
- 用户在本地刷新开发页面即可验收界面上的“加载更多论文”按钮；无须为本步骤重启后端，新增后端尾页边界只影响 arXiv 第 999 页之后的极深翻页。
