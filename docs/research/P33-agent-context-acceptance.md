# P33 研究助理上下文衔接

日期：2026-09-25。状态：实现完成，自动验收通过。

## 验收目标

在左侧成功检索论文后，用户可先让 Agent 列出书目信息，再用“根据刚才的检索结果”追问；Agent 应能沿用最近几轮对话的指代，并基于左侧检索范围重新取得可核验的书目元数据。不得把旧模型回答或浏览器提交的论文正文当作证据，也不能把元数据说成论文结论证据。

## 原因与实现

此前 Web 每次只向 Agent 发送当前 `question`，没有传入此前对话，也没有关联左侧搜索状态。Agent 因此无法解析“刚才的检索结果”，只能按本地目录状态返回证据不足。

- Web 保留最近一次**成功**检索的来源、查询词、年份区间和已加载页数；Agent 请求附带这一结构化范围与最近 4 轮对话（最多 8 条 user/assistant 消息）。更换来源后旧来源的搜索上下文会清空；面板提供清空对话操作。
- 后端契约严格限定来源为 OpenAlex、arXiv 或本地库，年份和页数有界。远程来源每次 Agent 请求按固定 API 和当前查询条件重读最多 3 页、每页 10 篇；本地来源从已导入目录读取。模型使用服务器观察到的书目字段，而不是直接相信浏览器提交的结果文本。
- 最近对话用于解析代词和任务延续，不作为事实证据。书目元数据可支持标题、年份、来源链接等字段；论文发现、方法或结论仍要求许可准入全文片段。
- 运行 trace 新增 `current_search_context` 事件；失败会保留安全错误码。来源在用户检索后、Agent 重读前发生变化或不可用时，界面和回答应如实反映，不能声称历史结果已重新核验。
- Agent 接口只允许固定字段；请求大小有限。该上下文没有增加任意 URL、shell、SQL、下载或写库能力。

## 用户验收步骤

1. 重启后端和 Web 开发服务，打开 PaperTrail。
2. 左侧选择 OpenAlex，检索 `Virtual Reality` 并设置 2022–2024；确认检索成功。若需要让 Agent 覆盖更多左侧结果，先点“加载更多”（Agent 上下文最多重读前 3 页，即 30 条）。
3. Agent 提问：“请用 OpenAlex 检索 Virtual Reality，年份限定 2022–2024。列出前 5 篇论文的标题、年份和来源链接，不要总结论文结论。”
4. 再提问：“根据刚才的检索结果，总结有哪些论文，并列出年份和来源链接。”检查第二次回答包含可点击的来源与对应“来源与证据”卡片；展开“运行记录与工程指标”，应看到 `current_search_context · ok`。
5. 改问论文“主要发现/结论是什么”。若本地没有获准全文证据，Agent 应说明证据不足，而不是仅凭标题/摘要或引用关系总结结论。

远程来源会按结构化搜索范围重新读取元数据，不保证两次请求之间上游数据库完全不变；trace 记录的是本次 Agent 实际读取状态。若重读失败，不能将前次回答当作本轮已核验来源。
