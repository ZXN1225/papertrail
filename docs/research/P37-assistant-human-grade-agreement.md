# P37：既有助手标签与人工评分一致性诊断

## 目的

P36 人工盲审完成后，利用相同 query-paper pairs，对照原 P13 `suggested_grade` 与人工 `reviewed_grade`。此诊断使用已有本地报告，不调用模型 API、不生成新标签，也不把助手建议视为金标。目标是检查已有 AI 辅助标注能否直接替代人工复核；结果用于判断是否值得开展后续、独立设计的 LLM-as-judge 校准。

## 复现

确保本机忽略目录中包含 P13/P14/P17/P36 报告及完成的 P36 CSV，然后从 `backend/` 运行：

```powershell
.\.venv\Scripts\python.exe -m app.cli.evaluate_p37_grade_agreement --confirm-human-review
```

默认结果写入 Git 忽略的 `backend/reports/p37-assistant-human-grade-agreement.json`，采用独占创建，不会覆盖输入。程序会重新构建 P36 盲审池并核验审计文件、CSV、P13 助手标签来源哈希和 query-paper 配对；输入必须完整且每个等级为 0–3。

## 结果

101 个配对候选、8 个查询的统计：

| 指标 | 结果 |
| --- | ---: |
| 完全一致率 | 30.7% |
| 相差不超过 1 级 | 64.4% |
| 平均绝对误差 | 1.218 |
| 二次加权 Cohen's kappa | 0.310 |

助手建议的等级分布为 0 分 81 项、1 分 0 项、2 分 9 项、3 分 11 项；人工分布为 0 分 20 项、1 分 27 项、2 分 19 项、3 分 35 项。混淆矩阵显示助手建议大量使用 0 分，而人工对许多相同候选评为 1–3 分，因此旧助手建议与人工判断存在明显等级分布差异。逐查询统计及完整混淆矩阵保存在本机 JSON 报告。

## 解释限制

- P36 查询按旧助手 qrels 上的排序分歧挑选；候选来自五种检索方法各自前五名并集，不是随机抽样。
- 只有一位人工评审，且未测量评审者之间的一致性。
- 该指标比较 P13 的既有助手建议与 P36 人工评分；不是独立、冻结提示词的 LLM-as-judge 校准实验。
- 结果只反映这批挑战集的配对差异，不证明助手相关性判断的一般能力、检索器总体质量或任何版本提升。

报告将 `exploratory_only` 设为 `true`，`quality_claim_allowed` 设为 `false`。后续若引入 LLM-as-judge，应先预注册提示词与评分规则，在独立多主题样本上运行，并与多位人工评审对照；在校准与误差分析完成前，模型输出只能作为候选建议。

## 验证

- P37 指标单元测试覆盖精确一致、容差一致、误差、混淆矩阵及无效配对拒绝。
- 完整后端测试、Ruff 检查与格式检查通过；Web Prettier 和根目录 `git diff --check` 通过。
