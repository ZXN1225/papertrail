## 下一轮可执行协议草案（运行前冻结）

1. **许可与布局登记。** 对新增每篇 PDF 逐一保存来源、版本、许可页 URL、许可标识、检查日期、文件 SHA-256 和版式桶；仅经逐篇许可核对后在本机导入。不把 PDF、全文或 SQLite 送入 Git。版式桶至少区分单栏、双栏、复杂表格/图注；扫描件/OCR 与纯图像推理作为明确的未支持桶，不纳入受支持准确率分母。
2. **任务设计与拆分。** 首轮目标 10–12 篇、约 40 题。建议预先固定 24 个可答和 16 个不可答任务，覆盖正文事实、否定、表格行/列、图注子图、跨论文不可比和证据不足；这是待冻结的设计比例，**不是当前数据**。按文档或主题组拆 dev/test，同一论文版本不能跨组。未看系统输出前记录题目、可答性、必要证据原始位置、来源版本和审核者；AI 起草题目不能标为人工金标。
3. **证据与解析器版本。** 标签锚定源 PDF SHA、页、元素/表格单元或原文字符范围，并记录 parser/chunker/index 版本。旧定位迁移到新索引时必须显式映射并复核；未映射标签不得计入新版本 recall。检索与生成采用同一冻结快照，禁止根据测试集失败继续调参后仍称其 holdout。
4. **离线优先。** 先做许可预检、结构/定位人审、BM25/Dense/Hybrid 同题只读检索及分桶报告，再决定是否进入付费模型阶段。报告逐项列分子/分母及失败类型；不能把“有任何支持回答”算成所有 gold 证据都检索到。
5. **付费模型运行。** 只有在固定 provider/模型、40 题清单、每题重复次数、并发/请求上限、总 USD 上限与停止条件后运行。原 48 次授权已经用尽。建议按同一题聚合 3 次稳定性，不把 120 次视作 120 道独立题；Skills 与多 Agent 另列请求数和成本。所有模型报告只留 Git 忽略目录，答案盲评在冻结输出后进行。
6. **判定。** 路线图建议目标是证据定位人工正确率 ≥95%、gold evidence recall@10 ≥85%、逐主张人工支持率 ≥95%、完整任务成功率 ≥80%、不可答正确拒答率 ≥90%、可答误拒率 ≤10%。这些是**建议目标而非当前成绩**；未达标记录返工和局限，不能缩小分母。若最终固定为 24 可答/16 不可答，recall 需至少 21/24、任务成功至少 32/40、不可答正确拒答至少 15/16、可答误拒最多 2/24；逐主张支持率须按实际主张数计算。多 Agent 仅在收益、成本和安全门槛都满足时考虑启用，现仍默认关闭。
