# I02 / T11 基础验收（实施前固定）

本轮为步骤 04：匿名会话、结构化需求与版本隔离。不开放模型、商品、报价或推荐；T11 的 Agent 状态机在 P5 扩展。

- PostgreSQL 新迁移建立 24 小时匿名会话、每会话单个画像及不可覆盖的 revision 历史；空库和 I01 升级均通过，回滚在隔离测试库验证。
- 随机签名 cookie，HttpOnly / SameSite=Lax / 生产 Secure 与 __Host- 前缀；数据库仅保存 token 摘要。服务端从 cookie 推导所有者，拒绝客户端 owner/revision 注入。
- 写入验证精确 Origin、JSON 和绑定会话的 CSRF；限制请求体与写入频率，Redis 配置后故障不能放开写入。开发 Redis 关闭时使用 PG 共享限流，不使用进程内无限制替代。
- 服务层集中校验与更新。金额严格整数分，预算有上限；patch 只修改显式字段，保留其他硬约束；来源元数据区分 explicit/default。切换设备保留预算/用途/地区，清除仅适用旧设备的字段。
- expected_revision 原子并发检查：相同旧 revision 的并发请求仅一个成功，其余 409；历史快照不覆盖。跨会话/过期/伪造身份读取与写入统一不可见 404。
- 新需求重置创建新会话并删除旧画像，旧 cookie 立即失效；删除当前会话级联删除内容。过期不可访问并提供清理命令；不承诺删除历史备份。
- 首页可以保存、刷新恢复、修改、处理多标签页冲突、显式开始新需求和删除需求；失败不显示已保存，冲突不自动覆盖；提示保存期限、暂无推荐。
- 后端真实 PG 集成涵盖隔离、CSRF/Origin、过期/伪造、并发、预算精度、模式切换、删除、依赖与限流；浏览器在 375/768/1440 验证真实 API 保存恢复与跨标签冲突。
- 同步 OpenAPI/生成类型、迁移/运行说明、TASKS/PROGRESS，运行 CI，创建增量 PR（base 为 I01 分支），不合并。完成后等待确认。
