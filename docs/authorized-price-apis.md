# 授权报价 API 申请与配置指南

更新：2026-09-22。此文档用于申请和核验来源权限；它不授予任何来源的抓取、存储或展示许可。

## 先选来源，不要先填密钥

本项目把“可调用 API”与“可公开展示数据”分开。每个来源都必须同时具备当前合同/平台规则允许的字段范围、应用凭据和可用于核验的测试 SKU。未满足任一条件时，来源保持禁用，仍使用 `manual-v1` 人工审核报价。

首批建议优先申请京东联盟：它的官方开放平台面向推广合作伙伴，提供按 SKU 查询推广商品信息的接口。该商品池和价格口径不等同于全量京东商品或每位消费者的最终结算价；会员、优惠券、地区、库存和配送条件必须随响应保存并展示限制。京东企业采购价格 API 仅适合已签采购合同、且 SKU 位于客户商品池的场景。

## 1. 京东联盟（第一接入目标）

1. 使用项目主体注册并登录 [京东联盟](https://union.jd.com/)，完成其要求的实名认证、媒体/推广渠道和结算资料。
2. 创建推广位/网站位，保存该推广位标识；不要使用个人账号 Cookie 代替应用凭据。
3. 在 [京东宙斯开发者中心](https://jos.jd.com/jdunion) 创建联盟应用，取得 App Key 与 App Secret，并按控制台要求申请商品查询/推广商品信息权限。
4. 阅读当前联盟协议与接口字段说明，确认本项目的读取、缓存、展示、跳转和价格更新频率都在允许范围内。把合同编号、控制台许可截图位置或内部合规记录写为 `JD_UNION_PERMISSION_REFERENCE`；不要把合同原文或个人资料提交到 Git。
5. 选一个允许测试的真实京东 SKU，记录其 SKU ID、地区、推广位、接口返回中的价格类型、库存/配送字段和活动/优惠限制。只有能精确对应厂商型号的 SKU 才能进入暂存。
6. 将凭据仅写到本机 `.env` 或部署平台密钥管理服务：

```text
AUTHORIZED_PRICE_SOURCES=jd_union
JD_UNION_PERMISSION_REFERENCE=internal-contract-reference
JD_UNION_APP_KEY=...
JD_UNION_APP_SECRET=...
JD_UNION_SITE_ID=...
```

保存后先执行后端配置测试；本阶段尚未包含联网客户端，所以不会因此发起请求。下一阶段的固定客户端会只调用已审查的京东联盟端点，不允许输入任意 URL。

## 2. 京东企业采购（可选，不与联盟混用）

1. 使用企业采购主体联系京东企业采购/客户经理，确认已签合同是否包含价格查询 API、客户商品池、地区及展示/缓存权利。
2. 取得企业应用的 Access Token 获取方式、合同价格口径和测试商品池。官方价格接口只查询客户商品池中的 SKU，且可返回合同类型相关价格。[接口说明](https://opendoc.jd.com/iopv2/iopv2/%E4%BB%B7%E6%A0%BC/%E6%9F%A5%E8%AF%A2%E5%95%86%E5%93%81%E5%94%AE%E5%8D%96%E4%BB%B7.html)
3. 把它作为未来独立 `jd_iop` 适配器申请，不要把企业 Token 填入本轮的 `jd_union` 变量。

## 3. 淘宝/天猫、拼多多（备选）

1. 在 [淘宝开放平台](https://developer.alibaba.com/) 或相应联盟/推广控制台创建应用，确认商品详情、搜索、价格和优惠接口对你的应用类型实际开放。
2. 在多多进宝/拼多多开放平台创建推广应用，确认商品池覆盖电脑硬件、响应是否包含所需价格与资格字段，以及允许展示和缓存的范围。
3. 分别取得 App Key、Secret、推广位或 PID、当前权限说明、一个真实测试 SKU 和回调/签名要求。
4. 将这些材料登记后再新增固定来源 ID 和适配器。不要把第三方“聚合 API”的网页描述视为原平台授权。

淘宝开放平台确有商品和促销类 API，但可调用权限随应用、卖家授权和订阅变化；创建应用后必须以控制台显示的当前权限为准。[商品 API 文档](https://developer.alibaba.com/docs/api.htm?apiId=66479)

## 4. 配件规格和厂商/分销商资料

报价 API 不能替代兼容性事实。CPU、GPU、主板、内存、SSD、电源和机箱应分别向厂商、总代或授权分销商申请产品资料包/API。申请时明确需要：精确料号、revision、规格字段、资料版本、区域、有效期、允许缓存/展示范围和变更通知方式。没有机器可读接口时，仍可使用获得许可的 CSV/Excel 文件，经 `manual-v1` 暂存、审核和发布。

## 交给项目审核的最小材料

每个来源提供以下材料即可开始适配器实施：来源名称、当前协议或权限记录位置、允许字段/用途、App Key/Secret 的**密钥管理位置**、推广位或站点标识、一个测试 SKU、地区、响应字段样例（脱敏）和预期更新频率。不要在聊天、PR、导入 JSON 或 Git 中发送 Secret、Token、Cookie、订单或个人信息。
